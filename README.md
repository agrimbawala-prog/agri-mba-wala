# AGRI MBA WALA

An original, responsive agriculture-platform website built with Next.js App Router, TypeScript, Tailwind CSS 4, and localised English/Marathi content. It uses original SVG illustration and copy; no source-site imagery, logo, or text is included.

## Start locally

1. Install dependencies with `bun install`.
2. Copy `.env.example` to `.env.local` and replace all placeholder values.
3. Start the development server with `bun run dev`.
4. Visit `http://localhost:3000`. The root selects `/en` or `/mr` from the browser's `Accept-Language` header.

Useful commands:

```bash
bun run dev
bun run lint
bun run build
bun run start
```

## Environment variables

| Variable | Required | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Yes | Canonical URL, sitemap, robots file, and social metadata base. |
| `NEXT_PUBLIC_WHATSAPP_NUMBER` | Before launch | WhatsApp number in international digits only. |
| `SUBMISSIONS_DB_PATH` | Local only | SQLite path, normally `./data/submissions.sqlite`. |
| `ADMIN_USERNAME` | Yes for `/admin` | Protected admin sign-in name. |
| `ADMIN_PASSWORD` | Yes for `/admin` | Protected admin password. |
| `ADMIN_SESSION_SECRET` | Yes for `/admin` | Long, unique HMAC signing secret. |
| `SUPABASE_URL` | Production option | Supabase project URL. |
| `SUPABASE_SERVICE_ROLE_KEY` | Production option | Server-only Supabase service-role key; never expose it to the client. |

Do not commit `.env.local` or a real Supabase service key.

## Forms and submissions

The registration and contact forms validate in the browser and again in `app/api/submissions/route.ts` with a shared Zod schema. A honeypot field rejects basic automated submissions. The local default is Node's `node:sqlite` database at `data/submissions.sqlite`, which is ignored by Git.

Vercel has an ephemeral filesystem, so a production Vercel deployment should set both Supabase variables. Once they are present, the same code uses Supabase's REST API instead of SQLite. Create this table in the Supabase SQL editor:

```sql
create table public.submissions (
  id bigint generated by default as identity primary key,
  kind text not null,
  audience text,
  name text not null,
  phone text not null,
  email text not null,
  district text,
  village text,
  subject text,
  message text not null,
  created_at timestamptz not null default now()
);
```

The service-role key is used only on the server. Do not add a browser policy that exposes it. `/admin` reads from the same store after a signed, HTTP-only admin session is established.

## Admin access

Open `/admin`. It redirects to `/admin/login` unless all three `ADMIN_*` variables are configured and valid credentials are supplied. Authentication is enforced inside server-side admin code rather than only in the proxy. Rotate the password and `ADMIN_SESSION_SECRET` any time access needs to be revoked.

## Content, language, and visual editing

- Site-wide identity and placeholder business details: `lib/site-content.ts`
- English and Marathi page copy: `lib/marketing-content.ts`
- Locale list and routing configuration: `lib/i18n/config.ts`
- Brand colors, spacing, responsive styles, and motion: `app/globals.css`
- Original SVG logo: `public/brand/agri-mba-wala-logo.svg`
- Original favicon: `app/icon.svg`
- SEO routes: `app/robots.ts`, `app/sitemap.ts`, `app/manifest.ts`, and `app/[locale]/opengraph-image.tsx`

Before launch, review every published business detail, policy, service description, and Marathi translation for accuracy. Keep operational claims aligned with the services actually available.

## Deploy to Vercel

1. Push the repository to the Git provider connected to Vercel.
2. Create a Vercel project with the repository root as the project directory.
3. Add the production environment variables above, especially `NEXT_PUBLIC_SITE_URL`, the three admin values, and both Supabase values.
4. Run the default `bun run build` build command (or let Vercel detect Next.js).
5. Set the production domain as `NEXT_PUBLIC_SITE_URL`, redeploy, then verify `/robots.txt`, `/sitemap.xml`, `/en`, `/mr`, form delivery, and `/admin`.

## Accessibility and performance

The page uses semantic sectioning, labelled inputs, keyboard-accessible navigation and FAQ controls, explicit focus states, a reduced-motion mode, responsive layout, original SVG art, and no remote images. This keeps the first-party surface lightweight while leaving real performance auditing to the final deployment environment.
